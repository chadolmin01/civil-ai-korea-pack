## 1) 변환 — 큐레이션을 pack 구조로

`scripts/build-pack.ts` 한 줄 실행으로 사이트의 라이브러리 카드 + 발굴 로그 → 4 파일:

- `selected/*.md` — 83 큐레이션 카드 (한국 적용 시나리오 포함)
- `candidates.jsonl` — 2,108 후보 전체 (자동 발굴 2,059 + 수동 시드 49, selected/rejected 상태)
- `selection_log.md` — 4 단계 필터 + 수동 promotion 이력
- `rejected_patterns.md` — 7 가지 탈락 사유 패턴

SQLite + ChromaDB + JSON 로컬. 외부 API 0.

## 3) 질의 — 사람이 손으로 묶어야 알았을 것들

가장 강한 케이스: **"한국 KDS 검증 워크플로우에 묶을 수 있는 도구 조합?"**

→ hybrid retrieval (vector + BM25 + graph) top-5:

```
mcp4ifc        0.907  자연어 IFC 모델 검증
text-to-cad    0.853  자연어 CAD 명령 스킬
hollowrc       0.790  중공 RC 단면 설계
structuralcodes 0.774 Eurocode 식 (KDS 포팅 템플릿)
blueprints     0.719  토목 / 구조 규준 계산식
```

**4 도구 조합이 한 줄 질의로 점수와 함께 자동 반환.**
이 조합을 *사람이* 묶으려면 카드 83 장과 카테고리 8 개를 한 번 정독해야 가능했다.

## 4) 메타-질의도 가능

탈락 패턴까지 흡수했기 때문에:

- *"라이센스 불명으로 탈락한 도구 중 다시 봐야 할 후보는?"*
  → `rejected_patterns` + `floorplan-analyzer` / `engineering-drawing-extractor`

- *"내가 누락한 BIM 도구가 있는지?"*
  → `assimp` / `ifcopenshell` / `revitlookup` / `hypar-elements`

큐레이션 *결과* 뿐 아니라 *과정* 도 질의 대상이 되는 게 핵심.
